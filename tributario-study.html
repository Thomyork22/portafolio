▮ El Requerimiento

Carga manual y desconexión con el SII

El proceso de gestión de certificados tributarios sufría de carga manual dispersa y falta de trazabilidad. Se requería un mantenedor centralizado capaz de procesar lotes masivos de documentos (PDF/ZIP), validarlos y sincronizarlos automáticamente con el Servicio de Impuestos Internos (SII), garantizando altos estándares de auditoría y seguridad.

▮ Análisis y Solución

Microservicios y Procesamiento Asíncrono

Se diseñó una arquitectura Cloud escalable. El frontend (SPA) se comunica a través de un API Gateway. Para evitar bloqueos durante la carga masiva, el procesamiento de PDFs y validación tributaria se delegó a Workers asíncronos apoyados en Redis, mientras que los documentos físicos se almacenan en repositorios de objetos (S3).

Cola de Procesamiento Asíncrono (MessageBus)

Fragmento del worker en Python (simulando Celery/Redis) encargado de procesar la carga masiva. Demuestra cómo se aísla la subida del documento a AWS S3 y la validación tributaria fuera del hilo principal de la petición HTTP, garantizando escalabilidad.

async_cert_worker.py
  1. import boto3
  2. from celery import shared_task
  3. from .models import CertificadoTributario, Auditoria
  4. from .sii_integration import SIIClient
  5.  
  6. s3_client = boto3.client('s3')
  7.  
  8. @shared_task(bind=True, max_retries=3)
  9. def procesar_lote_certificados(self, lote_id, file_path, user_id):
  10. try:
  11. # 1. Subida segura a Object Storage (AWS S3)
  12. storage_key = f"certificados/{lote_id}/{file_path.split('/')[-1]}"
  13. s3_client.upload_file(file_path, 'bucket-tributario-prod', storage_key)
  14.  
  15. # 2. Validación de negocio y parseo
  16. certificado = CertificadoTributario.objects.get(id=lote_id)
  17. certificado.storage_key = storage_key
  18. certificado.estado = 'PROCESADO'
  19. certificado.save()
  20.  
  21. # 3. Integración con SII mediante Adaptador
  22. sii_status = SIIClient.enviar_declaracion(certificado.folio)
  23.  
  24. # 4. Trazabilidad estricta
  25. Auditoria.objects.create(
  26. usuario_id=user_id, accion='PROCESAMIENTO_LOTE',
  27. entidad=f"Lote: {lote_id}", resultado=sii_status
  28. )
  29. return {"status": "SUCCESS", "sii_sync": sii_status}
  30. except Exception as exc:
  31. raise self.retry(exc=exc, countdown=60)

Decisiones de Diseño y Post-Mortem

Seguridad MFA y RBAC

Debido a la sensibilidad de la información financiera, se implementó seguridad por capas. Todo acceso requiere Autenticación Multifactor (MFA) obligatoria, y las acciones del sistema están protegidas por un modelo de Control de Acceso Basado en Roles (RBAC), limitando las vistas según si el usuario es Corredor, Auditor o Administrador.

Desacoplamiento con AWS S3

Almacenar archivos PDF y ZIP masivos en la base de datos relacional habría degradado el rendimiento. Se optó por un modelo híbrido: PostgreSQL maneja la metadata relacional, mientras que los archivos físicos residen en AWS S3 (Blob Storage), vinculados a través de un 'storage_key' único.

Patrón Adaptador para el SII

La comunicación con el Servicio de Impuestos Internos se encapsuló utilizando el patrón de diseño Adaptador. Esto protege la lógica de negocio interna del sistema; si el SII cambia su API o sus contratos de datos en el futuro, solo será necesario modificar la clase cliente de integración.
