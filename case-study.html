▮ El Requerimiento

Trazabilidad de hardware sin pérdida de datos

El Ministerio de Obras Públicas necesitaba centralizar sus activos físicos de tecnologías de información y eliminar la dependencia de planillas Excel dispersas. La información fragmentada dificultaba conocer la ubicación, el responsable y el estado de cada equipo, además de debilitar la trazabilidad del ciclo de vida del hardware.

▮ Análisis y Solución

Arquitectura web desacoplada y normalización

La solución implementa una SPA con React y Vite conectada a una API REST en Django y DRF. La base de datos utiliza catálogos estrictos normalizados en tercera forma normal (3NF), importación transaccional desde Excel y generación automatizada de actas de entrega, traslado y baja.

// EXCEL TRANSACTION ENGINE

Importación Transaccional y Normalización

Fragmento del motor de importación masiva. La operación se ejecuta dentro de una transacción, valida los registros contra catálogos maestros y usa inserción masiva para conservar la integridad del inventario y permitir rollback completo ante anomalías.

import_engine.py
  1. @transaction.atomic
  2. def procesar_lote_excel(file_obj, usuario):
  3. # 1. Crear registro de lote para trazabilidad y rollback
  4. lote = LoteImportacion.objects.create(usuario=usuario, archivo=file_obj.name)
  5.  
  6. workbook = openpyxl.load_workbook(file_obj)
  7. sheet = workbook.active
  8.  
  9. equipos_a_crear = []
  10.  
  11. for row in sheet.iter_rows(min_row=2, values_only=True):
  12. if not row[0]: continue # Saltar filas vacías
  13.  
  14. # 2. Normalización estricta contra catálogos maestros (3NF)
  15. marca = Marca.objects.get_or_create(nombre=str(row[3]).strip().upper())[0]
  16. tipo = TipoEquipo.objects.get_or_create(nombre=str(row[2]).strip().capitalize())[0]
  17.  
  18. # 3. Preparar instancia validada
  19. equipos_a_crear.append(Equipo(
  20. inventario=row[0],
  21. serie=row[1],
  22. tipo_equipo=tipo,
  23. marca=marca,
  24. lote_origen=lote
  25. ))
  26.  
  27. # 4. Inserción masiva optimizada
  28. Equipo.objects.bulk_create(equipos_a_crear)
  29. return lote.id

// PROJECT RETROSPECTIVE

Decisiones de Diseño y Post-Mortem

Despliegue On-Premise vs Cloud

Por políticas estrictas de seguridad de la información gubernamental, el sistema fue diseñado para operar exclusivamente dentro de la intranet local del MOP. El trade-off reduce la flexibilidad de escalamiento externo, pero mantiene la red institucional bajo control y evita exponer datos de infraestructura pública fuera del servidor físico.

Seguridad y Autenticación JWT

La API utiliza SimpleJWT y tokens Bearer para proteger las operaciones de inventario. Los interceptores de Axios adjuntan el token a las solicitudes protegidas y centralizan el manejo de respuestas de autenticación sin duplicar lógica en cada vista de la SPA.

Retrospectiva y Escalabilidad

Como evolución para la versión 2.0, se proyecta incorporar WebSockets para notificar fallas y cambios de estado en tiempo real, reduciendo la necesidad de actualizar manualmente las vistas del inventario y mejorando la respuesta del departamento TI.
